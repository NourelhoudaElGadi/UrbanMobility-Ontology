    Urban-Mobility-Ontology

    A semantic knowledge base for urban mobility and public transportation, with a specific focus on Demand-Responsive Transport (DRT) services operated by autonomous shuttles.

    Introduction

    Public transport systems rely on a wide range of heterogeneous data sources, including urban road networks, geospatial data, schedules, disruptions, traffic conditions, and passengers' mobility needs. These data are generally scattered across different sources and described using distinct models, limiting their interoperability and their use for decision support. This challenge is particularly significant in the context of Demand-Responsive Transport (DRT), especially when operated by autonomous shuttles, which require effective coordination with the broader public transport system.

    The proposed ontology provides a common semantic layer for representing knowledge related to demand-responsive public transport. It connects user demand (bookings, passengers, journeys, etc.) with the regular public transport supply represented using the General Transit Feed Specification (GTFS) standard, a multi-scale model of urban infrastructure, and events that may disrupt transport services and the urban network. Spatial and temporal dimensions are represented using existing standard models, namely GeoSPARQL and OWL-Time, respectively. The representation of events and disruptions relies on the reuse of the Simple Event Model (SEM) and the Transport Disruption Ontology (Dtx).

    The ontology was developed following an approach inspired by METHONTOLOGY and implemented in OWL using the Protégé ontology editor. It is populated with OpenStreetMap data covering part of the urban network in the La Rochelle urban area (France), GTFS data from the local public transport network, DRT requests in La Rochelle, and simulated disruption data.

    This ontology was developed within the framework of the YeloFlex project, an experimental initiative aimed at implementing a demand-responsive transport service operated by autonomous shuttles in the La Rochelle metropolitan area.

    Competency questions

    The questions that guided the design, with the terms that answer them and a SPARQL query tested on the knowledge graph.

    CQ1

    How can an on-demand transport request be represented, including its passenger, origin, destination, pickup time and drop-off time?

    Terms involved:

    • DRT:Reservation — DRT:hasPassenger → DRT:Passenger
    • DRT:Passenger — DRT:wait_at → GTFS:Stops
    • DRT:Reservation — DRT:assigned_to → DRT:Ride
    • DRT:Ride — DRT:includesTrip → DRT:Trips
    • DRT:Trips — DRT:Departs_from → GTFS:Stops
    • DRT:Trips — DRT:Arrives_at → GTFS:Stops
    • DRT:Reservation — DRT:selectedPickupTime → xsd:dateTime↗
    • DRT:Reservation — DRT:selectedDropoffTime → xsd:dateTime↗
    SPARQL query
    PREFIX DRT: <http://www.semanticweb.org/hp/ontologies/2024/6/OnDemand#>

SELECT ?reservation ?passenger ?origin ?destination ?pickup ?dropoff WHERE {
  ?reservation a DRT:Reservation ;
               DRT:hasPassenger ?passenger ;
               DRT:assigned_to ?ride ;
               DRT:selectedPickupTime ?pickup ;
               DRT:selectedDropoffTime ?dropoff .
  ?passenger DRT:wait_at ?origin .
  ?ride DRT:includesTrip ?trip .
  ?trip DRT:Departs_from ?origin ;
        DRT:Arrives_at ?destination .
}

    Tested on the knowledge graph: 334 result rows.

    CQ2

    Which scheduled routes or services can be used as alternatives or supplements to a given on-demand transport request?

    Terms involved:

    • DRT:Trips — DRT:Departs_from → GTFS:Stops
    • DRT:Trips — DRT:Arrives_at → GTFS:Stops
    • Infrastructure:Road_segment — geosparql:sfIntersects↗ → GTFS:Stops
    • Infrastructure:Road_segment — Infrastructure:IsPartOfStreet → Infrastructure:Streets
    • GTFS:StopTimes — GTFS:servesStop → GTFS:Stops
    • GTFS:StopTimes — GTFS:belongsToTrip → GTFS:Trips
    • GTFS:Trips — GTFS:hasRoute → GTFS:Routes
    SPARQL query
    PREFIX DRT: <http://www.semanticweb.org/hp/ontologies/2024/6/OnDemand#>
PREFIX GTFS: <http://www.semanticweb.org/hp/ontologies/2024/transport#>
PREFIX Infrastructure: <http://www.semanticweb.org/hp/ontologies/2024/7/Modélisation#>
PREFIX geosparql: <http://www.opengis.net/ont/geosparql#>

# Scheduled routes that stop in the same street as the departure or the arrival stop of an on-demand trip
SELECT DISTINCT ?trip ?end ?drtStop ?streetName ?route ?routeName WHERE {
  { ?trip DRT:Departs_from ?drtStop . BIND("departure" AS ?end) }
  UNION
  { ?trip DRT:Arrives_at ?drtStop . BIND("arrival" AS ?end) }
  ?trip a DRT:Trips .
  # the street of the on-demand stop
  ?segment geosparql:sfIntersects ?drtStop ;
           Infrastructure:IsPartOfStreet ?street .
  OPTIONAL { ?street Infrastructure:Nom_rue ?streetName }
  # the scheduled stops in the same street, and the routes that serve them
  ?segment2 Infrastructure:IsPartOfStreet ?street ;
            geosparql:sfIntersects ?busStop .
  ?stopTime GTFS:servesStop ?busStop ;
            GTFS:belongsToTrip ?gtfsTrip .
  ?gtfsTrip GTFS:hasRoute ?route .
  OPTIONAL { ?route GTFS:route_short_name ?routeName }
}
ORDER BY ?trip ?end ?routeName

    Tested on the knowledge graph: 1252 result rows.

    CQ3

    How can a disruptive event be represented by specifying its type, location, duration and impact on the transportation service?

    Terms involved:

    • sem:Event↗ — sem:eventType↗ → Dtx:RoadClosure↗
    • sem:Event↗ — Events:HasLocation → sem:Place↗
    • sem:Event↗ — sem:hasTime↗ → time:Interval↗
    • event:Event↗ — Events:HasImpact → Events:impact
    SPARQL query
    PREFIX sem: <http://semanticweb.cs.vu.nl/2009/11/sem/>
PREFIX Events: <http://www.semanticweb.org/nelgad01/ontologies/2026/10/Event#>
PREFIX time: <http://www.w3.org/2006/time#>
PREFIX owl: <http://www.w3.org/2002/07/owl#>

SELECT ?event ?type ?place ?begin ?end ?impact WHERE {
  ?event a sem:Event ;
         sem:eventType ?t ;
         Events:HasLocation ?place ;
         sem:hasTime ?interval ;
         Events:HasImpact ?impact .
  ?t a ?type . FILTER (?type != owl:NamedIndividual)
  ?interval time:hasBeginning/time:inXSDDateTimeStamp ?begin ;
            time:hasEnd/time:inXSDDateTimeStamp ?end .
}

    Tested on the knowledge graph: 18 result rows.

    CQ4

    Which on-demand ride reservations are affected by a disruption occurring in a given area and during a given time window?

    Terms involved:

    • event:Event↗ — Events:HasImpact → Events:PlaceImpact
    • Events:PlaceImpact — Events:ImpactsOnPlace → GTFS:Stops
    • DRT:Trips — DRT:Departs_from → GTFS:Stops
    • DRT:Trips — DRT:belongsToRide → DRT:Ride
    • DRT:Reservation — DRT:assigned_to → DRT:Ride
    SPARQL query
    PREFIX sem: <http://semanticweb.cs.vu.nl/2009/11/sem/>
PREFIX Events: <http://www.semanticweb.org/nelgad01/ontologies/2026/10/Event#>
PREFIX time: <http://www.w3.org/2006/time#>
PREFIX GTFS: <http://www.semanticweb.org/hp/ontologies/2024/transport#>
PREFIX DRT: <http://www.semanticweb.org/hp/ontologies/2024/6/OnDemand#>
PREFIX xsd: <http://www.w3.org/2001/XMLSchema#>

SELECT DISTINCT ?event ?reservation ?stop ?pickup WHERE {
  ?event Events:HasImpact ?impact ;
         sem:hasTime ?interval .
  ?interval time:hasBeginning/time:inXSDDateTimeStamp ?begin ;
            time:hasEnd/time:inXSDDateTimeStamp ?end .
  ?impact Events:ImpactsOnPlace ?stop .
  ?stop a GTFS:Stops .
  ?trip DRT:Departs_from|DRT:Arrives_at ?stop ;
        DRT:belongsToRide ?ride .
  ?reservation DRT:assigned_to ?ride ;
               DRT:selectedPickupTime ?pickup .
  FILTER (xsd:dateTime(STR(?pickup)) >= xsd:dateTime(STR(?begin)) &&
          xsd:dateTime(STR(?pickup)) <= xsd:dateTime(STR(?end)))
}

    Tested on the knowledge graph: 6 result rows.

    CQ5

    Which road segments are affected by a traffic event?

    Terms involved:

    • event:Event↗ — Events:HasImpact → Events:PlaceImpact
    • Events:PlaceImpact — Events:ImpactsOnPlace → Infrastructure:Road_segment
    • Infrastructure:Road_segment — Infrastructure:IsPartOfStreet → Infrastructure:Streets
    SPARQL query
    PREFIX Events: <http://www.semanticweb.org/nelgad01/ontologies/2026/10/Event#>
PREFIX Infrastructure: <http://www.semanticweb.org/hp/ontologies/2024/7/Modélisation#>

SELECT ?event ?segment ?streetName WHERE {
  ?event Events:HasImpact ?impact .
  ?impact a Events:PlaceImpact ;
          Events:ImpactsOnPlace ?segment .
  ?segment a Infrastructure:Road_segment .
  OPTIONAL { ?segment Infrastructure:IsPartOfStreet ?street .
             ?street Infrastructure:Nom_rue ?streetName }
}

    Tested on the knowledge graph: 6 result rows.
